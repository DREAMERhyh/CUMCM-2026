# Q2 零基础教学（08）：三层测试与 200 例实验

前面的算法讲完了。这一篇讲怎么**验证它没写错**——三层测试分工协作，再加一个
200 例的大样本实验来回答"这套方案到底靠不靠谱"。对应 `tests/q2/*`。

先交代一个词：本仓库的一等公民是"**保守性**"——宁可保留更多嫌疑，也不能漏掉真源。
所有测试都围绕这个展开。

## 1. 三层测试，各管什么

### 第 1 层：单元测试 `python tests/q2/test_unit.py`

直接对代码里的函数做断言，管"功能逻辑对不对"。挑几个重点例说明：

- `test_physical_region_is_bounded_and_contains_truth`：造一个已知真源 (220,280)，
  断言它真的落在 P₁ 内（验证保守性）。
- `test_plan_is_deterministic_...`：同一输入跑两遍结果**必须完全一样**
  （`selected_point`、FIM 点、FIM 指标都相等）——证明没有隐藏随机性。
- `test_selected_is_best_guaranteed_candidate`：保证池非空时应由 `min` 选出预期点。
- `test_no_guaranteed_candidate_falls_back_without_crash`：把保证域设空，
  应不崩溃地回退到任意候选，并让 FIM 报 `unavailable`。
- `test_all_scores_are_finite_...`：所有候选的 score 都是有限数、时间分解一致。
- `test_selected_measurement_keeps_compatible_truth`：用推荐点做第二次测量后，
  真源仍在后验区域、且半径不大于之前（定位不恶化）。

CLI 冒烟（`test_cli_writes_json_and_png`）：跑一次 `cli.py --demo`，断言出 JSON 和 PNG、
`method` 是 `time_budgeted_fim_pareto_hybrid`、近优域字段存在。

### 第 2 层：独立对拍 `python tests/q2/test_duipai.py`

**自己用自己的实现来验自己，可能出 bug 不自知。** 对拍的做法是：**用另一套更简单、
更慢但绝对正确的逻辑，独立复算每个输出**，看两套答案是否一致。用三类数据驱动：
`python tests/q2/gen_data.py --mode {random,boundary,adversarial}` 再 `--dir` 喂给对拍。

对拍复算了这些量：
- 有限候选池的最小解析项 == `baseline.selected_point`；
- 每个候选的 `guaranteed_reception` 标签 == 自己按 `max dist(点, 所有顶点) ≤ 1000` 重算；
- 时间记账 `T == dist/5 + (0或1) + 5`（逐候选）；
- 评分公式 `score == T + 0.5·R_wc`（逐候选）；
- 保证域顶点确为内近似 `max dist ≤ 1000 + 1e-6`；
- 可能域包含 P₁ 所有顶点；
- FIM 点可行（距源域顶点 ≤ 1000）、同口径复评分成立、执行时间 ≤ 预算；
- **"最终推荐半径不劣于离散基线"**——安全推荐的核心不变量；
- Pareto 前沿非空、两分支近优域均已生成且层级为 {5pct,10pct}。

对拍实现里正是用 `min(pool, key=(score,...))` 这种可审计的简单方式反推预期答案，
再与 `plan` 对齐。跑通即说明：规划器内部的排序、评分、回退、标签与独立 oracle 一致。

### 第 3 层：200 例基准 `python -B tests/q2/benchmark_200.py --count 200 --seed 20260911 --workers 16`

单用例看不出统计规律。200 例为了回答："这套双方案 + 混合裁决，
**在大量随机情况下到底赢不赢、输多少**。" 逐例结果存 JSON，汇总打出来。

## 2. 200 例的数据是怎么造的

`benchmark_200.py:generate_cases`（seed 固定可复现）：

```
① 均匀按面积采样一个源 G：源半径 = 1800·√U,  方位 U(0,2π)
② 真方位 θ₁ ~ U(0°,360°)
③ 检测点 S₁ = G − d·(cosθ₁, sinθ₁)，其中 d ~ U(100, 1000)
   保证 S₁ 与 G 距离在 [100,1000] → 首测必能收到信号
④ 若 S₁ 落在 1800m 圆外 → 丢弃重抽（保 S₁ 合法）
⑤ 注入误差 e ~ U(−1°,+1°)；测量示向 = (θ₁ + e) % 360
⑥ 频道 U(1..20)；current_channel 与检测频道相同（换频道时间为 0）
```

要点：**规划器只看到 `first_observation`（位置、频道、代误差示向度），
从不看合成真源 G**。G 只在评判阶段用来"断言 G 落在 P₁ 里"——又是验证保守性。

运行用 `ProcessPoolExecutor` 多进程并行，16 工人、122 秒（本机墙钟）。
选点部分跑了 200 例，**关掉了近优域采样**（`near_optimal_region_mode="off"`）来加速——因为
近优域只是画图素材，不影响选点。

## 3. 评价指标定义

| 指标 | 含义 | 好坏 |
|---|---|---|
| **主指标 R_wc** | 有限场景最坏后验最小包围圆半径 | 越小越好 |
| 工程分数 score | `T + 0.5·R_wc`（0.5 s/m 是工程权重，非题面常数） | 越小越好，并列参考 |
| 次级 T | 动作时间（移动/5+换频+5） | 越小越好 |
| FIM 指标 | 鲁棒信息量/秒 | 越大越好 |

每例都输出"新方案(FIM)相对旧方案(基线)"的三个差值（score、R_wc、T），
再做 `_comparison` 统计：赢/平/输的个数、均值、中位数。

## 4. 结果（2026-09-11 重跑）

| 指标 | 离散基线 | 连续 FIM | FIM 更优 |
|---|---:|---:|---:|
| **主指标 R_wc 均值** | 119.04 m | **70.08 m** | **200/200 = 100%**（均值差 −48.96 m） |
| R_wc 中位数 | 122.03 m | 75.05 m | 同上 |
| 工程分数均值 | 169.57 s | 174.80 s | 76/200 = 38% |
| 动作时间 | — | **+29.71 s** | 0/200（但 ≤30s 执行预算，设计如此） |
| FIM 指标 | — | — | 200/200 更高 |

**关键解读**：
1. 论"测完还剩多少嫌疑"，FIM **全胜**：把最坏半径从 119m 压到 70m。
2. 它代价是多跑约 30 秒——这正是"执行预算上限 +30s"的边界效果。
3. 因为 R 与 T 互相抵消，综合分只赢 38%——**所以必须分开报 R 和 T**，不能只看一个数。
4. 迈向上一代无预算 FIM（184/200，16 例恶化+609m）的**重大改进**：
   **加时间预算后恶化例被消除**，现在最坏后验半径 200/200 不劣于基线。

综合结论（README 已写死）：
> champion 以最坏后验半径为主指标、动作为次级；FIM 负责出候选，最终由
> 统一集合评分 + Pareto 规则裁决。这个 100% 是固定数据集、有限场景评分器上的
> 实验比例，不是连续全局最优概率。

## 5. 已知局限清单（写论文 / 答辩必背）

代码 `limitations` 数组和白皮书都如实声明，一句不多吹：

1. **源物理圆形区域**用外切正多边形近似（保守，但仍是近似）；
2. **保证域**是圆交集的内近似，可能域是 Minkowski 和的外近似；
3. **最坏情形**只在有限边界场景 + 有限误差端点计算，不声称连续全局最坏；
4. **连续 FIM** 只对测点坐标连续，源鲁棒性仍是边界场景近似；
5. **FIM 优化的是信息量替代目标**，最终用离散基线的集合评分同口径比较；
6. **近优域**是已验证局部采样点的凸包绘图近似，不是连续置信区域或严格子水平集证书；
7. **`optimality_claim`** 是 `numerical_near_global_for_fim_surrogate`，不是原问题全局最优证书；
8. **官方模拟器协议**仍待补充（`src/sim/` 负责，Q2 不直接发网络请求）。
