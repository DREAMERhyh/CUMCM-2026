# Q2 零基础教学（06）：混合裁决与最终推荐点

离散基线给了 1 个点，连续 FIM 给了 3 个（三档预算）。这一篇讲它们如何被
**统一复评分、过滤执行时间、构造 Pareto 前沿，再安全地裁决出一个最终推荐点**。
对应代码 `q2/planner.py:plan_measurement`（后半段）。

整套方法现在叫：

```
time_budgeted_fim_pareto_hybrid
```

意思是"加了时间预算的 FIM + Pareto 记录的混合裁决"。

---

## 1. 重新走一遍 `plan_measurement` 的主线

```
① 建源区域 P₁                          build_region_from_observations
② 建保证域/可能域                      build_candidate_regions
③ 生成离散候选点并评分                  generate_candidates + score_candidates
④ 在保证池里选离散基线点                selected（C 候选里 score 最小）
⑤ 连续 FIM 三档预算各出一解            optimize_continuous_fim → budget_solutions
⑥ 把所有解送回相同评分器复评分          score_candidates（同口径）
⑦ 执行预算过滤 + 选连续代表点
⑧ 构造 Pareto 前沿
⑨ 安全推荐：基线点 vs 连续代表点
```

---

## 2. 关键：什么是"同口径复评分"？

FIM 优化用的目标（`robust_fim_index_per_s`）和离散基线用的目标（score）**不是一回事**。
直接比数字不公平。

于是代码把 FIM 选的每个点，**再丢回 `score_candidates`**，用和离散基线**完全相同**的公式
重算它的 `T`、`worst_case_radius_m`、`score`：

```python
rescored = score_candidates(region, observations, [每个FIM点], ...)
```

这样整张桌子上所有点都有**同一单位**的 R_wc 和 T，才能公平比较。
（README 里反复强调的 "same-calibre rescoring" 就是这个。）

---

## 3. 执行预算过滤，选连续代表点

FIM 一口气给了 +15/30/60 三档点，但**实际上机器狗不能真的用 +60s 那档**——太慢。
所以设执行上限：

```python
execution_limit = T_baseline + fim_execution_extra_time_s   # +30 秒
```

把三档 FIM 点里 `T ≤ execution_limit` 的挑出来（不够再放宽到全部），
在这些"可执行"的点里按 **`(worst_case_radius_m, action_time_s, −FIM, point)`** 选最小值，
作为 `continuous_fim.selected_point`。

> 注意次序：先看**半径**，再比**时间**，FIM 只是并列第三位。
> 这和我们确立的"主指标 = 最坏后验半径，次级 = 时间"一致。

demo：三档里 +15s 和 +30s 都可执行（147.5、162.5 ≤ 162.5），选半径最小的 → +30s 档 (−358, 449.3)。

---

## 4. Pareto 前沿（时间 与 精度 的权衡折线）

把所有候选点（基线点 + 三档 FIM 点）放进一个集合，去掉被其他人"全面压过"的点：

`_pareto_front(items)`（`planner.py:110-121`）：

```
按 (T, R_wc, point) 升序排；
维持 best_radius=∞，遍历：
    若某个点的 R_wc < best_radius − 1e-9：加入前沿，更新 best_radius
```

结果是按动作时间递增的一条折线，折线上**每个点都不会被另一个点用更小的 T 和更小的 R_wc 同时压住**。demo 得到 **4 个 Pareto 候选**（基线 + 三档 FIM）。

**怎么看这张折线图**：越靠**左下**越好（时间短且半径小）。从离散点到 FIM 点，沿着折线
一路"用更多时间换更小的半径"——没有免费的午餐，但想知道"多花 X 秒能换来多少精度"，就看这条线。

---

## 5. 安全推荐：保证不劣于基线

最后一步，把候选压成 2 个：
- ① 基线选中点（source=baseline）
- ② 连续 FIM 代表点（source=continuous_fim）

在其中取 **`(worst_case_radius_m, action_time_s, point)` 词典序最小**者作为 `recommended`：

```python
recommended = min([基线点, FIM代表点], key=(R_wc, T, point))
```

**这就是"不希望它比基线差"的保证**：因为这两点里 R_wc 更小者当选，
所以 `selected.worst_case_radius_m ≤ baseline.worst_case_radius_m` 恒成立（浮点容差内）。
这一条在对拍里作为硬性检查 `check("最终推荐半径不劣于离散基线", ...)`。

demo：基线 R_wc=149.35、FIM R_wc=78.66 → 推荐 FIM 点，`recommendation_source="continuous_fim"`。

> 附带的工程观感：`comparison` 字段把基线与 FIM 的 score、半径差并列输出，
> 供论文写"输则差多少、赢则好多少"。

---

## 6. 顶层返回结构回顾（给 Q3/Q4 用）

`plan_second_point` / `plan_measurement` 的顶层返回里，**最关键的是 `selected_point` 和 `selected`**——
这是供 Q3/Q4 真正去跑的推荐点。其余字段是审计：

| 顶层字段 | 内容 |
|---|---|
| `selected_point` / `selected` | **最终推荐点**及其详情 |
| `recommendation_source` | `"baseline"` 或 `"continuous_fim"` |
| `baseline` | 离散基线结果（含 selected、near_optimal_regions、meta） |
| `continuous_fim` | 连续分支（三档 budget_solutions、fim_surrogate_best_point、selected…） |
| `pareto_front` | 时间—精度折线候选 |
| `comparison` | 两方案 score 与半径的并排对比 |
| `candidate_regions` / `candidates` / `region` / `limitations` | 审计与近似声明 |
