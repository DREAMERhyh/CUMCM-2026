# Q2 零基础教学（04）：离散基线——给候选点打分并选点

上一篇生成了 46 个候选点。这一篇讲怎么对每个点做"最坏情况压力测试"，
得到时间 T 和最坏后验半径 R_wc，再综合成分数并挑出**基线选中点**。
对应代码 `q2/planner.py:score_candidates` 和 `common/time_model.py`。

记住最终评判的核心口号：

> 每个候选点 s，都要被问两件事：**过去要多久？（时间 T）** 和
> **测完之后嫌疑范围最坏还能有多大？（最坏后验半径 R_wc）**

---

## 1. 先看板上写的常量（Q2Config）

所有阈值集中在一个 dataclass `Q2Config` 里（`planner.py:19-41`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `error_deg` | 1.005 | 示向误差半宽（比题面的 1° 略放大一点，更保守） |
| `arena_radius` | 1800 | 赛场半径 m |
| `min_receive_radius` | 1000 | 最小可能接收半径 m |
| `max_receive_radius` | 1500 | 最大可能接收半径 m |
| `uncertainty_seconds_per_metre` | 0.5 | 把"剩余半径米数"折算成"等效秒数"的权重 |
| `circle_sides` | 24 | P₁ 里圆的近似边数 |
| `candidate_region_sides` | 72 | 候选域圆近似边数 |
| `scenario_limit` | 8 | 评分用的源场景上限 |

`circle_sides`(24) 用于区域近似，`candidate_region_sides`(72) 用于候选域，
一个偏粗一个偏细，是为了"区域可以粗、候选域要紧"的工程取舍。

## 2. 时间成本 T(s) 怎么算

`common/time_model.py:measure_cost`：

```python
def measure_cost(previous, target, current_channel, target_channel):
    return TimeBreakdown(
        movement_s   = dist(previous, target) / 5.0,   # 速度 5 m/s
        switching_s  = 0.0 if current_channel == target_channel else 1.0,
        measurement_s= 5.0,                             # 固定检测时间
    )
```

```
T(s) = movement + switching + measurement
     = dist(S₁, s)/5  +  (0 或 1)  +  5
```

**手算验证**（`verify_manual.md` 里的标准例）：
- 从 (0,0) 移到 (3,4)，距离 5 m，`movement = 1 s`；
- 同频道：`1 + 0 + 5 = 6 s`；
- 换频道：`1 + 1 + 5 = 7 s`。

**demo 的基线点**：基线选中点 (4.17, −96.46) 距 S₁==(-600,-300) 约 637.5 m，
所以 `movement = 127.5 s`，同频道 `switching=0`，`measurement=5`，`T = 132.5 s`。符合输出。

## 3. 最坏后验半径 R_wc(s) 的第一步：选"源场景"

真源在 P₁ 里不确定，没法把每个 g 都试遍。代码取一组**代表性场景**：

```python
scenarios = representative_points(P₁.vertices, scenario_limit)
```

`representative_points`（`common/domain.py`）：P₁ 的每个顶点 + 每边中点 + 质心，
再确定性**下采样到 `scenario_limit=8` 个**——既覆盖边角又控制计算量。

demo：P₁ 三角形，算法取到 **7 个场景**，例如
`(-600, -300)`、`(634.9, 561.0)`、`(608.3, 607.1)`、
各边中点 `(621.6, 584.1)`、`(17.5, 130.5)`、质心 `(4.2, 153.5)`、另一下采样点 `(214.4, 289.4)`。
场景越多越接近"最坏情况"，但上限被限住以保证速度（有限场景，不是连续证明）。

---

## 4. 对每个"场景 + 误差"算后验区域 P₂

对候选 s、场景 g、输入误差 e（±1.005° 或 0），模拟"在 s 又测了一次"：

```
P₂ = P₁ ∩ B(s, 1500) ∩ W(s, θ(g,s)+e)
```

- `B(s,1500)`：在 s 能收到信号的外切圆；
- `W(s, θ(g,s)+e)`：若真源在 g、误差是 e，则 s 测得的示向应该是 θ(g,s)+e 附近的扇区；
- 相交后 P₂ 就是"两次测量完，真源还被限定在哪个更小的范围"。

代码 `_posterior_radius`（`planner.py:42-58`）把假想新示向交给
`common/domain.py:extend_region_with_observation`：保留当前后验的全部半平面，只对新增接收圆补端点切线和超差切线，再求 P₂ 的**最小包围圆半径**。特殊处理：
- 若 P₂ 无界 ⇒ 返回 `inf`（这次测量等于没帮上忙）；
- 若 s 距 g ≤ 5 m ⇒ 返回 `min(5, 当前半径)`（太近无法分辨方向）。

---

## 5. 汇总出最坏半径 R_wc(s)

`score_candidates` 对每个 s 累加一批"半径候选"，取**最大值**：

```python
for target in scenarios:
    if dist(s, target) > 1500:
        radii.append(current_radius);  continue   # 收不到，保持不变
    for error in (±1.005°, 0):
        radii.append(_posterior_radius(...))        # 正常算后验
    if dist(s, target) > 1000:
        radii.append(current_radius)                # 未知R可能no_signal
if not guaranteed_reception:
    radii.append(current_radius)                    # 非保证，难说
worst_radius = max(radii, default=current_radius)
```

其中 `current_radius = P₁ 最小包围圆半径`（demo 里 755.5 m）——代表"不测就保持原样"的兜底。

直观解读：**R_wc(s) = 在最不利的真源位置、最坏的误差方向上，测完 S₂ 后嫌疑范围最大仍有多大。**
它越小越好，就是"最坏情况还能压缩到多小"。

demo：基线点的 `R_wc = 149.35 m`，比不测的 755.5 m 小多了——说明它是个有效的观测点。

---

## 6. 综合分数与选点

工程综合分（仅用于并列报告，不是题目给死的公式）：

```
score(s) = T(s) + 0.5 × R_wc(s)     (uncertainty_seconds_per_metre = 0.5)
```

demo 基线点：`score = 132.5 + 0.5×149.35 = 207.18`

**选点的容器与排序**（在 `plan_measurement`）：
1. 全部 46 个候选先按 `(score, −fim_proxy, point)` 排序，编候选人号 C01…；
2. 挑出**保证接收**的子集 `guaranteed`（12 个）；
3. 若保证接收非空，**只在保证池里选**；否则回退全部候选（`pool = guaranteed or scores`）；
4. `selected = min(pool, key=(score, −fim_proxy, point))`。

`fim_proxy`（`_fim_proxy`，一个简化的 `sin 夹角 / (d1·d2·时间)`）作为并列分——分数相同填平手。
