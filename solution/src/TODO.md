# Q3/Q4 尚未实施的后续优化

本文件只保留未实施事项。Q3 的“清除失败后条件复测”和“有限场景总虚拟时间滚动优化”均已完成，说明见 `q3/README.md`，独立结果见 `../test_res_q3_failed_clear_remeasure.md` 与 `../test_res_q3_rolling_time.md`。

## 1. Q4 位置—方向联合适配

Q4 当前显式关闭 Q3 的两个新增优化。后验除源位置外还包含未知发射方向，后续必须同时模拟：

- 发射方向场景；
- 候选测点是否位于可见半平面；
- `direction` 与 `no_signal` 分支；
- 四个方向探测点必须整体执行时的成本；
- 定向源清除失败后的信息更新。

在这些条件实现前，不得把 Q3 的“距离不超过 1000 m 即保证接收”直接用于 Q4。

## 2. 更完整的多源路线优化

当前 Q3 滚动估值用“当前源最坏清除路线终点到最近其他源后验中心”近似后续任务。它修正了续程为零造成的长距离折返，但不是全局路线最优。可继续研究：

- 把多个活动源的候选测点和清除路线端点一起纳入小规模路径规划；
- 比较最近邻、插入启发式、2-opt 和有限束搜索；
- 保留当前 0.2 s 截止，超时回退已验证策略；
- 使用新的训练种子选择参数，再用未见验证种子汇报。

## 3. 滚动评价缓存与场景扩充

当前 0.2 s 截止通常返回 `partial`，即只评价完候选列表前部。可在不改变 Q2 API 的前提下缓存：

- 后验区域和观测序列的稳定哈希；
- Q2 候选点；
- 候选点—场景测后后验；
- 后验清除网格和路线终点。

缓存命中后再增加源位置场景、候选点或边界误差采样。任何缓存都必须包含当前位置、当前频道、活动源集合和配置，避免复用过期成本。

## 4. 官方模拟器验证

队员先按 `tests/sim/verify_manual.md` 完成 Q3/Q4 smoke，再决定是否运行完整演练。需核对：

- 控制台平均用时与模拟器总虚拟时间、清除成功数一致；
- Q3 每次滚动评价没有导致现实时间超限；
- `partial/fallback` 不产生重复动作或无动作退出；
- Q4 未误启用全向源滚动评价；
- 正式测试前保留足够的 `/exit` 安全余量。
