## 3. 一个贯穿全文的演示案例

为了让所有数字可验证，整套文档反复使用同一个本地合成案例——用
`sim.fake.FakeSimulator` 里放了一个"全向干扰源"：

```python
源位置 = (1200, 100)，频道 3，接收半径 1000 m
```

也就是：赛场里只在**频道 3** 上有一个真实干扰源，藏在 (1200, 100)；
另外 19 个频道（1、2、4、5…20）**一个源都没有**。

运行命令（在 `solution/` 目录下）：

```powershell
python src/q3/cli.py --max-refinements 2 --fim-cpu-time-limit-s 6 --max-actions 300 --output output/q3_offline/teach_demo.json
```

我本机实际运行得到的结果（教学文档全篇引用的那套数字）：

| 指标 | 数值 |
|---|---|
| 动作总数 | **140**（enter×1 + measure×137 + clear×1 + exit×1） |
| 被清除的频道 | **[3]** |
| 判定为"无源"的频道 | **[1, 2, 4, 5, …, 20] 共 19 个** |
| 离线虚拟时间 | **约 2959.614 s**（约 49 分钟） |
| 退出原因 | `user_exit` |

清掉频道 3 的关键几步（时间序）：

- 第 24 个动作：在覆盖点 **(1500, 0)** 测频道 3，第一次拿到 `direction`，示向 **162.46°**——表示源大概在正南偏西方向。
- 扫描完其余 19 个频道后，全部 `no_signal` ⇒ 判定无源。
- 频道 3 靠一次测角只知道大概方向 → 进入**细化**，在 **(777.1, -35.4)** 和 **(777.7, -34.9)** 又测两次，拿到 17.01°、17.75°，三次测角**交会**把源锁定到约 (1200, 100)。
- 第 138 个动作：在 **(1196.1, 95.7)** 执行 `clear` → `success`。源到该点的精确距离约 5.8 米，完全在 20 米清除半径内。

> 这套数字是教学复现用的**本地模拟结果**，不是官方成绩，也不能用来预测正式案例表现
> （正式案例会有 10~16 个源、要用官方模拟器）。原因在第 07 篇讲。
