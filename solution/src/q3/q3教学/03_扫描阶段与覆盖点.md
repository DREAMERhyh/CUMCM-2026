# Q3 零基础教学（03）：扫描阶段 —— 7 个覆盖点 + 20 个频道

策略的第一个大阶段是 `scan`：像"撒网"一样，把整个赛场**系统地扫一遍**，
找出哪个频道上真有源。这一篇讲清三个问题：

1. 该**站在哪些点**量，才能保证"任何可能存在的源至少被收到一次"？（覆盖构造）
2. 每个点上，怎么把 **20 个频道**一个个测过去？（扫描顺序）
3. 扫完怎么判"这个频道多半无源"？（absent 决策）

---

## 1. 为什么要"覆盖"，而不是随便测？

还记得 demo 里第一次测到频道 3 是在 **(1500, 0)** 吗？为什么偏偏是那里？
因为全向源离探测点 ≤ `receive_radius`（接收半径）就能被收到，而 receive_radius
理论最大 1500 m。所以：

> 如果我想"证明一个频道无源"，就必须保证：**该频道即使藏在赛场任意角落，
> 也有某个探测点能收得到它**——否则我测不到它，只是因为站得不够近。

要想做到这一点，最简单的办法是：**让探测器们"手拉手"围住整个赛场**，
用很多测点把 1800 m 半径的大圆整个盖住，任意一个可能的源都落在某个测点 1500 m 内。

代码给的方案是：**7 个点**（`coverage.py` 的 `ring7()`）就够了。这就是"覆盖点集合"。

---

## 2. 覆盖点怎么算出来？（`ring7`）

`coverage.py` 里两行代码就造出了 7 个点：

```python
def ring7():
    return [(0.0, 0.0)] + [
        (1500.0*math.cos(k*math.pi/3), 1500.0*math.sin(k*math.pi/3))
        for k in range(6)
    ]
```

拆开看：**1 个原点 + 6 个点**。那 6 个点怎么来的？

- `k` 从 0 到 5，共 6 个角度：`k*π/3` 弧度 = `k*60°`。
- `math.cos`、`math.sin` 算出"半径 1500、每隔 60° 一个"的单位圆上的点。
- 于是得到正六边形的 6 个顶点。

所以 `ring7()` = **圆心 (0,0) + 半径 1500 的正六边形 6 顶点**：

```
            (750, 1300)
(-1500,0) ●              ● (1500, 0)      ← 6 个顶点均匀围一圈
                ●(0,0)                        + 1 个圆心
(750,-1300)          (750,-1300) 方向省略
（实际 6 顶点在 0°,60°,120°…300°）
```

用一张表列出：

| k | 角度 | x = 1500·cos | y = 1500·sin | 点 |
|---|---|---|---|---|
| 0 | 0° | 1500 | 0 | (1500, 0) ← demo 第一次测到频道3的点 |
| 1 | 60° | 750 | 1299 | (750, 1299) |
| 2 | 120° | -750 | 1299 | (-750, 1299) |
| 3 | 180° | -1500 | 0 | (-1500, 0) |
| 4 | 240° | -750 | -1299 | (-750, -1299) |
| 5 | 300° | 750 | -1299 | (750, -1299) |

> 为什么是"半径 1500 的正六边形"？因为 1500 正是最大接收半径，正六边形让相邻测点
> 距离合适、又让每个顶点能覆盖到相邻方向。测试（第 07 篇）验证过：**随机在半径 1800 的
> 大圆内撒 5000 个"可能源"，每个源到这 7 个点的最近距离都不超过 1000 m**——远小于 1500，
> 说明覆盖相当充分、留有余量。

## 3. 每个点怎么扫 20 个频道？（`_scan_action`）

有了 7 个点之后，策略要回答："下一个 measure 测哪个点、哪个频道？"
这段逻辑在 `policy.py` 的 `_scan_action`，我们来逐行拆。

```python
def _scan_action(self, state):
    # 外层：遍历 7 个覆盖点
    while state.scan_point_index < len(self.coverage_points):
        # 进入一个"新点"时，第一次要建立本点的频道扫描顺序
        if not state.scan_order:
            state.scan_order = [state.current_channel] + [
                channel for channel in range(1, 21)
                if channel != state.current_channel
            ]
            state.scan_channel_index = 0

        # 内层：在当前点，逐个频道测量
        while state.scan_channel_index < len(state.scan_order):
            channel = state.scan_order[state.scan_channel_index]
            # 已经清除/已建档案的频道，跳过
            if channel in state.cleared or channel in state.sources:
                state.scan_channel_index += 1
                continue
            # 否则：返回一个 measure 动作，测当前覆盖点上的这个频道
            return self._action(state, "measure",
                                self.coverage_points[state.scan_point_index],
                                channel, "scan")
        # 当前点所有频道都测完 → 移到下一个覆盖点，重置顺序
        state.scan_point_index += 1
        state.scan_order = []
    ...
```

两层循环的意思：

- **外层**：依次走到每个覆盖点（`scan_point_index` 从 0 到 6）。
- **内层**：在当前覆盖点，按一定顺序把 20 个频道每个都测一遍。

**频道顺序怎么定？** 有个小窍门：

```python
state.scan_order = [state.current_channel] + [其他频道]
```

把**当前已经切在的那个频道**排最前、其余频道按 1..20 排后面。
因为切频道要花 1 s（`time_model`），先测当前位置已选中的频道**能省一次切换时间**——
这个细节说明策略很在意时间开销（第 06 篇会算账）。

**跳过什么？** 已清除（`cleared`）或已建档（`sources`）的频道不必再扫。
"sources"里有的频道说明已经测到 direction，进入 resolve 单独处理了，不用在 scan 里扫。

## 4. 一次"measure"动作在 scan 阶段的完整账

回到 demo：每做一次 `measure`，`FakeSimulator` 会：

1. 从**当前机器位置**移动到**目标覆盖点**（机器人依次到 7 个点）；
2. 切频道（同频道 0 s，不同 +1 s）；
3. 用 5 s 测一次；
4. 返回该频道此刻的结果。

下面用 demo 的前几个动作感受一遍（对照你跑出来的 `teach_demo.json`）：

| 序号 | 覆盖点 | 频道 | 结果 | 说明 |
|---|---|---|---|---|
| 1 | enter | — | accepted | 进场 |
| 2 | (0,0) | 1 | no_signal | 原点测频道1 |
| 3 | (0,0) | 2 | no_signal | 原点测频道2 |
| … | (0,0) | 频道3 | no_signal | 原点离源 (1200,100) 约 1204m >1000m，收不到 |
| … | (0,0) | 其他… | no_signal | 原点测完所有频道 |
| … | (1500,0) | 频道3 | **direction 162°** | 离源仅约 316m，收到了！ |
| … | 其余点 | … | no_signal | 其余点照样把各频道测一遍 |

这就是为什么 137 个 measure：**7 个点 × 20 个频道 ≈ 140 上下**，绝大多数频道测出来
都是 no_signal，只有频道 3 在某个近点测到了 direction。

> 直观上，scan 阶段就是在做"地毯式排查"：用固定几个点、把 20 个频道全部"问一遍"。
> 谁的答案有 direction，谁就被重点照顾（进入 resolve）。

## 5. 扫完所有点之后：判定"无源"

`_scan_action` 最下面有一行——

```python
state.absent = set(range(1, 21)) - set(state.sources) - state.cleared
state.phase = "resolve"
```

扫完 7 个点后，策略把所有频道「减去已建档的 sources」「减去已清除的」剩下的一批，
**一次性全部判为 absent（无源）**。

**这样判安全吗？** 依赖上面第 1 条的覆盖构造：既然任何可能的源都会被某个覆盖点收到
信号，那么"7 个点位全部没信号"的频道，几乎可以认为真没有源。这就是"覆盖 + 排除法"
的精髓——**不是逐个证明没有，而是靠覆盖保证测不到=没有**。

demo 里 19 个 absent 频道就是这么来的：除频道 3 外，其余所有频道在 7 个覆盖点上
全部 no_signal，于是全部划入 absent。

> 注意一个边界：如果某个频道真的存在、但恰好在某个覆盖点附近测成了 `near`，
> 那它不是 no_signal 而是 near，会触发 `forced_clear`（第 04/05 篇讲到）。
> 扫描阶段主要处理"远距离排查"。

## 6. 顺带认识另一个覆盖构造：`strip_clear_points`（保底用）

`coverage.py` 里还有一个 `strip_clear_points`，它生成长条带状的一串点，用于**清扫**——
第 05 篇会详细讲，这里先埋个伏笔认识它：

```python
def strip_clear_points(sensor, bearing_deg):
    theta = math.radians(bearing_deg)          # 把"示向角"换成弧度
    u = (cosθ, sinθ)                            # 源方向单位向量
    n = (-u[1], u[0])                           # 垂直方向的另一单位向量
    for row, offset in enumerate((-20, 0, 20)):  # 三条平行条带
        for index in ...:                        # 每条带沿线走 76 步
            yield (sensor[0] + 20*index*u[0] + offset*n[0], ...)
```

它在"源大致方向"上铺出三条平行的、间距 20 m 的探测点序列——因为清除需要源在 20 m
内，用这种 20 m 步长 + 三条带的网格，能保证**源只要落在这条带状区域里，总有某个
探测点离它 ≤20 m**。这是"保底清除"的基础（第 05 篇会算担保）。

过于细节不必现在背，先记住：**scan 用 `ring7` 找"哪里有源"，clear 保底用
`strip_clear_points` 找"贴着源的哪几厘米清"**——两种覆盖服务不同目的。
