# Q3 零基础教学（04）：定位区域与细化 —— 从"一个方向"到"一个准点"

扫描找到一次 `direction` 后，机器只知道自己"朝某个方向看到了源"。这一篇讲：
**怎么只靠几次测角，把源一步步锁定到 20 米内，然后一击清除。**

这是整套策略最精华、也是最依赖前面所有工作的一篇。用一个真实例子带：demo 里
频道 3 的三次测角最终把源锁到了 (1200,100) 附近。

---

## 1. 一次 direction 给你什么信息？

假设你在位置 S、某频道上测到 `direction`，角度 θ（±1° 误差）。
这一刻你其实只知道三件事：

1. **频道上有源**（在接收半径内）。
2. 源的位置 **S 与源连线的方向 ≈ θ**（允许偏 ±1°）。
3. 源到 S 的距离 **≤ 1500 m**（最大接收半径）。

"方向 ±1°" + "距离 ≤1500" 这两条合起来，画在图上就是一块**扇形/月牙**区域——源一定
在这块区域里，但具体在哪还不知道。

> 这就是"嫌疑区域"（region）的起点：**一堆"源可能在哪"的约束交出来的凸多边形**。
> 一次测角 → 一块区域；几次测角 → 几块区域交叠 → 越来越小、越来越准。

代码里负责把它变成"凸多边形"的是 `common/domain.py` 的 `build_region_from_observations`。

---

## 2. 候选区域怎么"长"出来？（`build_region_from_observations`）

原理一句话：**每次观测都是一组几何约束，把所有约束半平面的交集算出来，就是源的全部可能位置。**

三种约束（都写成"半平面 `a·x+b·y ≤ c`"）：

| 约束来源 | 数学表达 | 直观 |
|---|---|---|
| 赛场本身 | 到原点 ≤ 1800 m | 源绝对在赛场内 |
| 一次 direction 的距离上限 | 到观测点 S ≤ 1500 m | 远了收不到 |
| 一次 direction 的方向 | 示向 θ ± 1° | 一个窄扇形 |

把这些半平面全交起来，就得到一个**凸多边形** `region`。

代码里的函数按顺序叠约束：

```python
planes = circle_outer_planes((0,0), arena_radius=1800, ...)   # ① 赛场外圈
for obs in observations:
    if obs.result != "direction": continue                      # 只要 direction
    planes.extend(circle_outer_planes(obs.position, 1500, ...)) # ② 到该点≤1500
    planes.extend(bearing_planes(obs.position, obs.bearing_deg, error)) # ③ 方向±1°
region = intersect_halfplanes(planes)                            # ④ 全交起来
```

> 这里有个**保守性**的关键讲究：圆形一律用**外切正多边形**近似（`circle_outer_planes`）。
> 外切 = 每个半平面都比真实圆"更宽松一点"，于是交集**绝不会丢掉任何真实可能的源的
> 位置**——我们要宁可区域比真实大一点，也绝不把真的源误排除掉。这就是教学里反复强调的
> "保守"二字：**宁大勿假**。

`intersect_halfplanes` 在 `q1/geometry.py`，输出就是这个区域的口径：它的**顶点列表**、
**直径**、**最小包围圆**（下面要用的关键量）。这个函数我们起名"半平面求交"，简单说就是
把一堆"源不能在哪"都画出来，剩下重合的部分就是"源一定在"的地方。

## 3. 用哪个数字衡量"定位有多准"？—— 最小包围圆半径

区域算出来了，策略需要**一个数字**来判断"我现在准到能清除了吗？"。
这个数字就是 **区域最小包围圆（MEC）的半径** `R`。

- 最小包围圆 = 能罩住整个区域的最小的圆（第 07 篇会讲它的精确算法——枚举 1/2/3 个
  支撑点）。
- 半径 `R` 的含义是：**源可能在以圆心为中心、半径 R 的圆内任意处**。

在 `policy.py` 的 `_resolve_action` 里，策略这样读它：

```python
radius = track.region["minimum_enclosing_circle"]["radius"]
```

然后做判断（下一节）。

> 直觉：R 越大 → 源的可能范围越大 → 越"模糊"；R 越小 → 越"准"。
> 目标是让 R 小到 **≤ 20 m**：这样只要站到圆心附近 clear，源铁定在 20m 范围内，一击即中。

---

## 4. 守卫判断：什么时候能"自信清除"？（certified clear）

`_resolve_action` 里的核心分支：

```python
track = state.sources[remaining[0]]
radius = track.region["minimum_enclosing_circle"]["radius"]
if radius <= 19.9 and not track.certificate_failed:
    center = track.region["minimum_enclosing_circle"]["center"]
    return self._action(state, "clear", center, track.channel, "certified_clear")
```

翻译成大白话：

> **如果源的可能区域能用一个半径 ≤ 19.9 m 的圆罩住**，那么我就认为已经"锁定"到了
> 20 米以内的精度，直接站到那个圆的**圆心**执行 `clear`。这个 clear 称为
> **certified_clear（被证明的清除）**——因为我用几何"证明"了源一定在圆心 20m 内。

为什么是 19.9（小于 20）？给自己留 0.1 米的裕量，防止浮点误差刚好卡在临界线上。
`clear` 的成功条件是"源距清除点 ≤ 20 m"，留出裕量更稳妥。

demo 里最后的清除点为什么是 **(1196.1, 96)**？因为三次测角交会的区域，其最小包围圆
圆心约在 (1196, 96)，半径已被压到 ≤19.9 m，可直接清除；源真实在 (1200,100)，
差约 5.8 m，远在 20m 内——**一次 clear 就 success**。

## 5. 还不够准怎么办？—— 细化（refine）

但现实里，一次 direction 给的信息太少，MEC 半径往往好几千米，离 20 m 差得远。
这时就得**再测几个点**，让区域缩小。这步叫**细化**。

细化要做的事有两件：
1. **想**：接下来去哪个点再测一次，能让 MEC 缩小得最快、同时别太费时间？
2. **做**：开过去测，拿到结果后重算区域，再看 R 是否 ≤ 20。

`refine` 在 `_resolve_action` 看到 `radius > 19.9` 时被触发：

```python
if track.refinements < self.max_refinements:   # 还没把细化次数用完
    point = self._refinement_point(state, track)   # 想：用 Q2 算推荐点
    return self._action(state, "measure", point, track.channel, "refine")
```

**核心就藏在 `_refinement_point` 里**——它直接把决定权交给了 Q2 的规划器。

---

## 6. 核心委托：`_refinement_point` 调用了 Q2 的什么？

```python
def _refinement_point(self, state, track):
    plan = plan_measurement(
        track.region, track.observations,
        current_position=state.position,
        current_channel=state.current_channel,
        target_channel=track.channel,
        config=self.q2_config,
    )
    return tuple(plan["selected_point"])
```

它调用 `q2/planner.py` 的 `plan_measurement`，传参：

- `track.region`：当前的嫌疑区域；
- `track.observations`：该频道已经攒下的全部测角历史；
- `current_position` / `current_channel`：机器现在在哪、切在哪个频道；
- `target_channel`：要测的目标频道；
- `config`：一批超参数（含 FIM 的人时间预算、误差界 1° 等）。

返回值里取 `selected_point`——**Q2 综合"信息量 + 时间成本"后推荐的"下一个最优测量点"**。
这就是 Q3 里"细化"两个字背后的引擎。

> 我们需要知道：Q3 的细化**不是自己发明的**，而是**调用 Q2 已经写好的规划器**，让它
> 基于当前已知的所有测角，推荐一个"信息量大、别太贵"的测点。这就是教学文档 00 里说的
> "Q2 混合推荐点"。细节（连续 FIM、Pareto、预算分档）都在 `q2教学/` 里，这里点到为止，
> 只讲它在 Q3 中怎么被用。

demo 里两位细化测量点 **可见地印证了流程**：

| 动作序号 | 位置 | 示向 | 作用 |
|---|---|---|---|
| 24 | (1500, 0) | 162.46° | 第一次发现源：只知道"大概在南偏西"（区域很大） |
| 136 | (777.1, -35.4) | 17.01° | 细化①：Q2 推荐点，在新的角度观察 |
| 137 | (777.7, -34.9) | 17.75° | 细化②：继续逼近 |

三次测角从**完全不同的方向**看同一个源 → 交会区域急剧缩小 → MEC 半径压到 20 米内。

> 见微知著：Q2 选的细化点不在源正前方、也不在正侧方，而是选在"能同时把方向误差压小"
> 的斜侧位——这正是"信息最大"思路的体现。

---

## 7. 细化的边界：`max_refinements` 是什么？

`max_refinements` 限定了**每个频道最多细化几次**。demo 里设为 2，所以频道 3 最多能
重测 2 次（刚好用完 136、137 两下）。为什么要限？

- 实战里时间宝贵，无限细化会把时间耗光；
- 一般两三次测角交会已足够把 MEC 压到 20m 内；
- 万一两次还不够，就进入第 05 篇的**保底清除**通道，而不是死磕。

若细化次数用完、R 还是 >20，策略会走 `strip_clear_points` 保底（下一篇）。

---

## 8. `near` 结果：一个特殊捷径

`apply_response` 里对 `measure_result == "near"` 有一个特别分支：

```python
if result == "near":
    state.forced_clear = (action.position, action.channel)
    return
```

如果某次测量返回 `near`，说明**源就在这个探测点 5m 以内**——根本不用再细化定位！
策略会记下"强制去这里清除"，下一次 `next_action` 直接在该点 clear（跳过了所有定位流程）。
这是个省时间的好设计：**距离已经近到爆表，直接打了算**。

（demo 没有触发 near，所以没体现，但代码里这条捷径是存在的。）
