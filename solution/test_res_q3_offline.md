# 历史记录：B-Q3 Offline 验收结果

> 本文件仅保留重构前的离线原型测试记录，不代表人工或官方模拟器验收。

## 验收范围

当前未接入官方模拟器。本文件只验收全向源策略的离线状态机、7点覆盖构造、首次测向扇区有限清除点列、虚拟时间、请求幂等、协议负载和有限终止。

## 实际执行

```powershell
python -B -m unittest discover -s code/tests -p 'test_q3_offline.py' -v
```

最新结果：7 项测试全部通过，耗时 2.294 s。

- 固定种子在目标圆内抽取5000个位置，所有位置到7点布局的最近距离均不超过1000米；连续空间保证仍来自解析覆盖证明。
- 对首次测向局部矩形按10米与13.16米间隔抽查，228个蛇形清除点的最大最近距离小于20米。
- 附件给出的完整动作序列复算为199秒。
- 相同request_id和相同动作重试不会重复推进本地虚拟时间。
- HTTP负载构造不会把内部 `kind` 字段发送给官方接口。
- 一个固定全向源的离线规则场景在1000动作上限内完成清除，并为其余19个频道形成完整覆盖后的无源证书。
- Q3 使用 Q2 顶层混合推荐点；连续 FIM 已启用，单次真实墙钟上限为 6 s，绘图用近优域关闭。
- 固定全向源端到端测试不再设置 `max_refinements=0`，而是与在线默认一致地执行两次真实 Q2 细化规划，并断言两次均被调用。

全项目回归共 76 项全部通过，耗时 66.071 s；Q4 继承 6 s 参数后的 4 项离线测试也全部通过。

## 离线演示

```powershell
python src/q3/cli.py --max-refinements 2 --fim-cpu-time-limit-s 6 --output output/q3_offline/online_like_demo.json
```

固定演示使用一个本地合成全向源和在线同款两次细化配置，执行 140 个动作，清除频道 3，离线虚拟时间约 2959.614 s；终端明确报告细化上限 2、单次 FIM 墙钟上限 6.000 s。该数字只检查记账与终止流程，不是官方成绩，也不能用于估计正式案例表现。
