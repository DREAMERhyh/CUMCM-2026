```powershell
D:\anaconda3\envs\pytorch_env\python.exe run_drill.py --problem 3 --mode policy --robot-id "你的参赛队号" --scan-layout pure_ring8 --confirm-ready --confirm-policy
```

说明：
- `--scan-layout` 可选 `ring7` / `hub_ring6` / `pure_ring8`；缺省跟随策略当前默认（当前为 `ring7`，锁定投票后再切换）。
- `--mode policy` 是 run_drill 默认，也可省略。
- 跑 Q4 演练时把 `--problem 3` 换成 `--problem 4`（不加 `--scan-layout`，Q4 专用覆盖点）。
- 参数含义：`--max-refinements 2`（每源最多 2 次细化）、`--fim-cpu-time-limit-s 6`（每次规划的墙钟上限）、`--max-actions`（Q3 默认 **8000**；9-12 演练实证 14-16 源局的 resolve+fallback 可超 1000 动作）、`--exit-safety-margin-s 15`（快到现实时限时提前 15 秒安全退出）。

## D. 对账记录方法（核心）

每局演练结束，把摘要里的数字填进下面这个 CSV（建议存为
`solution/output/sim/drill_records.csv`，就是仓库相对路径 `output/sim/drill_records.csv`）：

**CSV 模板**（列名 + 示例行；第 1 行就是列名）：

```csv
game_no,problem,test_case_code,official_total,cleared,absent,cleared_plus_absent,consistent,scan_layout,virtual_time_s,average_clear_time_s,note
1,3,WA6Q-XRC2-KVMP-2KGF,13,13,7,20,TRUE,pure_ring8,2633.0,202.54,
2,3,XXXX-YYYY-ZZZZ-WWWW,12,12,8,20,TRUE,pure_ring8,2541.2,211.77,
```

逐列说明（对照 `output/sim/..._summary.json` 的同名字段）：

| 列 | 从哪来 |
|---|---|
| `game_no` | 你按 1、2、3… 自己编号 |
| `problem` | 3 或 4 |
| `test_case_code` | **模拟器界面**显示的案例编码（演练也应抄 GUI 编码；没抄时用输出文件时间戳并备注） |
| `official_total` | **模拟器界面**测试结束时显示的干扰源总数（演练才会显示） |
| `cleared` / `absent` | 摘要 JSON 的 `cleared_count` / `absent_count` |
| `cleared_plus_absent` | 两者之和（策略把未发现频道判缺席；完整局应为 20） |
| `consistent` | 【修正口径】`cleared == official_total` **且** `cleared_plus_absent == 20` 填 `TRUE`，否则 `FALSE`。注意：不是"cleared+absent == 官方总数"——官方总数是"有源频道数"，absent 包含判为无源的频道，两者没有求和等于关系 |
| `scan_layout` | 本局用的布局（如 `pure_ring8`） |
| `virtual_time_s` | 摘要 JSON 的 `virtual_time_s`（总虚拟时间） |
| `average_clear_time_s` | 摘要 JSON 的 `average_clear_time_s`（= 总虚拟时间 ÷ cleared 数） |
| `scan_phase_s` | 分析脚本给出：首个 /clear 前的累计虚拟时刻（含首源定位细化，详见脚本注释） |
| `note` | 现象备注（漏检、报错、连接失败、安全退出等，**必须写案例编码**） |

判定要点：
- **`consistent=FALSE` 且 `cleared < official_total`** ＝漏检/未完成，立即进 E 节；
- 摘要里"时间对账：不一致"（差值超过 1 毫秒才算，1~3 微秒的舍入差属正常）也记入 `note`；
- 摘要含 `action_cap_safety_exit` 标记＝本局因客户端动作上限提前退出（未完成），
  属环境问题不是策略漏检，重新跑一局即可（默认上限已提高到 8000）。

发回方法：把 CSV 文件路径或内容直接粘贴回 Claude 会话即可。

## E. 判定与回退规则

1. **连续 5–10 局全部 `consistent=TRUE`** → 布局锁定 **`pure_ring8`**。
   （口径：`cleared == 官方总数` 且 `cleared+absent == 20`；`action_cap` 未完成局不计入
   "不一致"，但也不计入"一致"局数，需重跑补足。）
2. **任何一局 `consistent=FALSE`（cleared < 官方总数）**：
   - **立即停止**，记录该局案例编码与现象；
   - 若为 `action_cap_safety_exit`：重新跑一局即可（默认动作上限已从 1000 提到 8000）；
   - 若为真实漏检：用 `--scan-layout hub_ring6` 重跑同类案例验证（hub 布局覆盖裕量更大）；
   - 把两局的摘要/CSV 发回分析，**修好前不进入正式测试**。
3. **程序报错 / 连接失败 / 超时 / accepted=false**：记录现象与 JSONL 路径，**不擅自改代码**，发回处理。
4. 完整局 `cleared_plus_absent < 20`：频道证书不完整（策略 bug 或中途退出），立即发回分析。
