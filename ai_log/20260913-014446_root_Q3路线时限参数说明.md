# AI 使用记录：Q3路线时限参数说明

## 输入

```text
并把路线时限从 0.25 秒比较到 0.5/1 秒   这个时限是写死的还是可以通过运行参数更改
```

## 运行结果

只读核对了 Q3 策略构造函数、本地 CLI、在线模拟器 CLI 和路线配对基准。确认 0.25 秒只是各入口的默认值，并未写死；本地和在线命令均可通过 `--route-cpu-time-limit-s` 改为 0.5 或 1 秒，策略内部也可通过 `Q3Policy(route_cpu_time_limit_s=...)` 传入。该参数必须大于 0，且仅在启用 `insertion_2opt` 或 `beam_cached` 路线模式时影响路线求解；路线关闭时传入不会产生路线优化。基准脚本另有 `--beam-route-cpu-time-limit-s`，用于把 beam_cached 的时限与 insertion_2opt 分开比较。未修改代码，未运行测试或模拟器。
