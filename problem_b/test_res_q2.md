# B-Q2 验收结果

## 验收范围

本次验收覆盖第二检测点的连续候选域、离散候选生成、保守物理区域、有限场景最坏半径评分、FIM排序基准、命令行JSON输出和PNG可视化。Q2规划器只接收检测位置、频道和示向度，不接收干扰源真值。

第一观测后的源区域由以下约束构成：±1.005°示向扇区、半径1800米目标域、以第一检测点为圆心的1500米最大接收圆。两个圆域采用外切正多边形，因此近似是保守外包，不会因离散化排除真实源。

## 实际执行

```powershell
python -B -m unittest discover -s code/tests -p 'test_q2.py' -v
```

最终结果：9项测试全部通过，耗时35.049秒。覆盖内容包括：

- 物理区域有界且包含满足误差界的合成真值；
- 相同输入得到确定的相同选点；
- 连续保证接收域是1000米圆交集的安全内近似，连续可能接收域是1500米圆盘Minkowski和的保守外近似；
- 存在保证接收候选时，返回集合评分最低的保证候选；
- 保证候选为空时安全退化到带无信号分支的候选；
- 非direction输入被拒绝；
- 所有候选分数和时间均为有限合法数值；
- 对所选第二测点构造一组相容观测后，后验区域仍包含真值且不确定半径不增；
- CLI成功输出可解析JSON和非空PNG。

第一次曾使用 `python -B -m unittest code/tests/test_q2.py -v`，因Python标准库模块 `code` 与本项目目录同名而没有加载测试。改用与Q1一致的 `unittest discover` 后正常执行；这不是算法失败。

## 结论与限制

Q2代码达到当前离线验收要求。连续域只对“能否接收”给出可审查边界，交会角和定位收益由后续有限场景评分处理；正式选择使用有限候选和有限边界场景，不声称求得连续空间全局最优。FIM只作解释和对照。1.005°包含0.005°接口两位小数裕量，不是新的题面概率分布。

测试中发现Windows默认控制台编码无法输出上标字符 `²`，已将CLI单位改写为 `m^2` 后复测通过；不影响JSON数值或图形。
