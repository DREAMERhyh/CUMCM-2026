# B题算法代码快速上手指南

## 1 这套代码已经能做什么

这套代码把B题分成四层：

- Q1：根据多次示向度计算干扰源定位区域、区域直径和覆盖圆；
- Q2：只有一次有效示向度时，选择下一处检测点并画出候选区域；
- Q3：为全向源执行“覆盖发现、复测定位、清除、有限保底”的离线策略；
- Q4：在Q3基础上处理定向源，增加多方位复核和121点全局保底。

Q1和Q2已经完成本地算法与可视化测试。Q3和Q4目前只有离线规则测试，还没有在官方模拟器中演练，因此不能把离线时间和清除结果当成比赛成绩。

## 3 最快体验Q2

运行固定示例：

```powershell
python code/q2/cli.py --demo --no-show `
  --output output/q2/q2_demo.png `
  --result-json output/q2/q2_demo.json
```

自定义第一检测点：

```powershell
python code/q2/cli.py `
  --first -600 -300 35.89 `
  --channel 1 `
  --no-show `
  --output output/q2/my_plan.png `
  --result-json output/q2/my_plan.json
```

`--first` 后三个数依次是检测点x坐标、y坐标和示向度。角度以正东为0°，逆时针增加。

图中浅蓝区域是第一观测后的源位置域，橙色是探测器的可能接收连续域（外近似），绿色是保证接收连续域（内近似）；彩色圆点是实际参与优化的离散候选。红色五角星是集合评分选择，黄色叉号是FIM基准。右图按候选编号比较前15个离散候选在有限场景下剩余的不确定半径。

JSON中的主要字段：

- `selected_point`：建议的第二检测点；
- `candidate_regions`：连续的保证接收域和可能接收域及其近似方向；
- `guaranteed_reception`：对保守区域是否保证在1000米以内；
- `worst_case_radius_m`：有限场景中最坏的后验最小包围半径；
- `action_time_s`：移动、频道切换和检测的预计虚拟时间；
- `fim_baseline_point`：只按局部信息几何选择的对照点。

Python调用方式：

```python
from common.models import BearingObservation
from q2 import plan_second_point

first = BearingObservation((-600.0, -300.0), 1, "direction", 35.89)
plan = plan_second_point(first)
print(plan["selected_point"])
```

从 `problem_b/` 直接运行自写脚本时，需要把 `problem_b/code` 加入 `PYTHONPATH`，或者把脚本放在 `code/` 下。

## 4 Q3和Q4离线演示

```powershell
python code/q3/cli.py --output output/q3_offline/demo.json
python code/q4/cli.py --output output/q4_offline/demo.json
```

这两个命令只调用 `runtime/fake_simulator.py`，不会连接官方模拟器，也不会消耗正式测试次数。输出JSON记录每个动作和响应，可用于检查状态机。

Q3先用7点布局扫描尚未知的频道；发现信号后保存示向区域；区域足够小时到包围圆中心清除，否则做有限次Q2复测，最后用首次测向扇区上的228点蛇形清除作为有限保底。

Q4沿用同一状态机，但全局未发现证书改用121点网格。这个网格很慢，却能覆盖任意未知发射方向；它是兜底方案，不是推荐直接用于正式测试的高效方案。

## 5 以后怎样接官方模拟器

`runtime/http_client.py` 已实现同步HTTP适配和同ID同内容重试，但没有任何默认命令会自动连接或调用 `/enter`。接入前应先在官方模拟器中选择“演练测试”，等待接口就绪，再由队员明确运行连接代码。

最小连接形式如下，执行后会真正调用 `/enter`，所以不要在正式测试页面随意运行：

```python
from q3 import Q3Policy
from runtime.http_client import HttpRobotClient
from runtime.runner import run_policy

client = HttpRobotClient(robot_id="你们的参赛队号")
summary = run_policy(Q3Policy(), client)
```

接入官方模拟器前必须补做：

1. 用演练模式核对四类接口返回值；
2. 检查断网重试仍使用相同request_id和请求体；
3. 测量单次RPC现实耗时和日志大小；
4. 先跑Q3，再跑Q4；
5. 保存失败案例，不能只保留成功结果。

## 7 怎样理解当前验证结论

- `test_res_q1.md`：Q1完整验收；
- `test_res_q2.md`：Q2完整本地验收；
- `test_res_q3_offline.md`：Q3只完成离线和理论验收；
- `test_res_q4_offline.md`：Q4只完成离线和理论验收。

Q2的连续域只表达接收可行性；交会角好坏由离散候选的后验区域评分处理。该评分不是连续空间全局最优证明。Q3/Q4的本地规则模拟器也不是官方模拟器替代品。论文中可以使用覆盖证明、算法结构和离线实验，但正式清除率与时间必须来自官方模拟器导出的三次正式测试日志。

## 8 常见问题

**为什么第一观测后区域已经有界？**  
Q1只研究纯示向交集，所以单次观测无界；Q2还知道源在1800米目标圆内，并且成功接收意味着距离第一检测点不超过1500米，因此物理区域有界。

**为什么圆画成多边形？**  
程序使用外切正多边形包住真实圆，便于继续使用Q1半平面算法。它会略微放大不确定区域，但不会错误删除真实源。

**Q3为什么可以判定某频道无源？**  
只有完成有证明的全局覆盖后，该频道始终无信号，才能形成无源证书；单个检测点无信号不能这样判断。

**Q4为什么比Q3慢很多？**  
定向源背面完全无信号，7点覆盖不再充分。121点网格是容易证明但保守的兜底，后续必须通过官方演练优化扫描、复测和清除调度。
