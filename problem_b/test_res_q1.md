## 1. 验收范围

本次验收只覆盖 B 题问题1：

- 根据检测点坐标和实测示向度构造正向 ±1° 误差扇区；
- 求多个扇区的纯交集，并区分空集、无界、点、线段和有界多边形；
- 求凸定位区域直径及端点；
- 判断以该直径线段为直径的圆能否覆盖定位区域；
- 输出逐次加入观测的区域收缩信息、JSON 和 PNG/SVG 图形；
- 补充计算最小包围圆，但不把它冒充为 Q1 原文要求。

未纳入：Q2 第二检测点选择、Q3/Q4 模拟器客户端、搜索与清除策略。

## 4. 几何算法验证

### 4.1 旋转卡壳与独立 oracle

固定种子生成2000组随机点集，每组3至60个点，先求严格凸包，再比较：

- 正式算法：`diameter_calipers`，旋转卡壳；
- 独立基准：`diameter_bruteforce`，枚举全部顶点对。

全部2000组的直径在8位小数比较下相同，返回端点间距离也与报告直径一致。空集、单点、线段、含共线点及“最长点对恰为边”的情形另有解析测试。

### 4.2 区域分类与不变量

通过的回归包括：

- 空集、无界扇区、无界条带、有界矩形、单点和线段；
- 跨0°示向度及只保留正向扇区；
- 改变绘图范围不改变真实直径；
- 平移全部坐标不改变直径；
- 新增相容观测后，有界区域直径不增；
- 求解器只读取检测点、状态和示向度，不读取源真值。

### 4.3 “直径圆不一定覆盖”的反例

解析反例：边长20的等边三角形。

|量|结果|
|---|---:|
|定位区域直径|20 m|
|直径圆半径|10 m|
|最小包围圆半径|`20/sqrt(3) ≈ 11.547005384 m`|
|直径圆能否覆盖|不能|

两次测向的四边形反例也已直接通过 Q1 入口计算：

|量|结果|
|---|---:|
|顶点数|4|
|区域直径|63.250325289 m|
|直径圆半径|31.625162644 m|
|直径圆最大超出|0.153034491 m|
|最小包围圆半径|31.625531267 m|
|直径圆能否覆盖|不能|

因此程序结论与题目理论结论一致：对一般凸定位区域，答案不是恒定“能”，必须检查具体顶点。

## 6. 非法输入与失败行为

- 示向度不在 `[0,360)` 时返回非零退出码，不生成图形；
- 误差界不是有限数或不在 `(0,90)` 时拒绝计算；
- `--no-show` 未给出 `--output` 时由命令行参数检查拒绝；
- 空集和无界区域不返回伪造的有限直径；
- 输出扩展名不是 PNG/SVG 时拒绝保存。

## 7. 测试中发现并修复的问题

1. 首次将主算法切换为旋转卡壳后，数值直径正确，但线段情形的端点顺序与旧 API 不一致。已把端点稳定为字典序，并重新运行全部测试通过。
2. CLI testbench 最初强制按 UTF-8 解码 Windows 子进程输出，在系统代码页环境中造成断言失败。已改为使用 Python 当前区域设置解码；该问题只影响测试捕获，不影响 JSON 或图形数值。

## 8. 已知限制

- 几何计算使用普通双精度和显式容差，不是任意病态输入的精确算术证明；极端近平行或尺度差异巨大的输入仍应高精度复核。
- 半平面交采用便于审查的 `O(m³)` 小规模枚举基线；适合 Q1 的少量观测，但不是大规模最优实现。
- 最小包围圆采用二点/三点支撑圆穷举，最坏 `O(n⁴)`，定位多边形顶点很少时可接受。
- 旧浏览器界面本次只做 JavaScript 语法回归；当前正式 Q1 验收入口是 `code/plot_cli.py`。

## 9. 验收结论

当前实现满足 B-Q1 的可运行交付要求：输入实测示向度后，可以独立得到定位区域、直径、直径端点及直径圆覆盖结论；主算法有独立 oracle 和随机 testbench，数学反例、退化状态、数值导出和图形端到端流程均有自动化证据。上述限制已明确记录，不影响普通题目尺度下的 Q1 验收。
